# 项目总览

## 1. 产品定位

火蜥蜴工具箱当前不是一个“多页面桌面壳”，也不再以“轻量 IDE”作为近期完成标准；它是一个面向单个使用者的个人桌面工具工作台。用户在同一窗口里浏览工具、配置参数、执行任务、查看日志、管理 SSH 连接，并在需要时导出工具或回收远程执行结果。

## 2. 当前真实状态

- 已完成桌面宿主重构主线，Wails 后端与 Vue 前端已经形成稳定的工作台骨架。
- 已接通本地执行链路，旧 Go/Python 工具通过桥接继续复用。
- 已接通基础远程执行链路，但 SSH 安全、密钥认证和部分状态流还没有收尾。
- 已接通日志导出与单工具导出：Python 默认导出脚本源码，Go 支持源码/二进制两种导出模式，并支持工具级导出目标平台记忆。
- 已接通 Go 环境配置主链：自动检测、本地选择、官方 SDK 下载、下载任务进度/速度/停止、环境检查、删除当前托管 SDK、`<无 SDK>` 清除、状态栏环境提示。
- 已接通 Python 环境配置主链：自动检测基础 Python、本地选择、托管虚拟环境创建/重建、`<无 Python>` 清除、动态依赖扫描检查、一键安装依赖、状态栏环境提示。
- 已接通 Rust 工具主链：Rust 工具已经进入本地执行、远程执行、单工具导出、构建缓存与产物中心矩阵。
- 已接通 Rust 环境配置主链：支持 `<无 SDK>` / 自动探测 / 手动选择 三种模式，支持 Rust 环境目录选择、Zig SDK 选择、托管 Rust / Zig 下载、`cargo-zigbuild` 与常用 targets 补齐，以及状态栏环境提示。
- 已接通工作区内置工具入口：活动栏独立入口、左侧搜索卡片、右侧专属标签页，以及一组前端本地工具页面。
- 文档已经按“当前有效 / 历史归档”重新整理，旧方案不再与现状混排。
- 当前产品已经足以覆盖“拿起来就跑工具、必要时切远程、看结果、导出或收回结果”这条主用途；后续重点是收口和补顺手，而不是继续长成更重的平台。

## 3. 当前能力边界

### 已落地

- 单页工作台：活动栏、侧边栏、标签工作区、参数区、执行终端。
- 工具加载：内置 YAML manifest + 旧工具桥接并行工作。
- 工作区内置工具：独立侧边栏入口、独立标签页类型、本地即时处理页面。
- 执行路径：本地执行、基础远程执行、日志流回传、任务状态同步。
- 连接管理：SSH 连接的列表、表单、测试、编辑、删除。
- 导出能力：单工具另存为导出、最近导出目录、Go 导出模式、导出后自动打开目录、工具级导出目标平台记忆。
- 远程结果闭环：执行后结果探测、当前页签“下载结果”入口、单文件下载、目录远端打包后下载、下载任务抽屉与完成后打开目录。
- Go 环境管理：本地 Go 选择、官方 SDK 下载与切换、下载任务进度/速度/停止、环境检查、删除当前托管 SDK、显式禁用当前 SDK、状态栏提示与设置页入口。
- Python 环境管理：基础 Python 选择与切换、托管虚拟环境创建/重建、显式禁用当前环境、动态依赖扫描检查、一键安装依赖、状态栏提示与设置页入口。
- Rust 工具：当前至少包含 `LAS/LAZ 体素抽稀与强度预览`，并支持本地执行、远程执行、单工具导出与构建缓存复用。
- Rust 环境管理：模式切换、Rust 环境目录选择、Zig SDK 选择、托管 Rust / Zig 下载、`cargo-zigbuild` 补齐、常用交叉编译 targets 补齐、状态栏提示与设置页入口。
- 本地偏好：收藏夹、最近使用、参数历史、部分界面设置与设置页签记忆。
- 工作区内置工具集：当前包括时间处理、JSON 工具、Base64 工具、URL 工具、Hash 摘要、JWT 查看。

### 未闭环

- SSH 链路的安全收口与密钥认证全链路一致性。
- 参数级远程路径选择能力，以及远程/本地路径语义拆分。
- 远程结果能力的轻量历史补位与少量细节打磨，但主链路已经可用。
- 独立 SSH 终端页签与少量交互打磨。
- 若干设置项、帮助文案与状态流的收尾打磨。

### 当前不作为主线

- 不继续把“工具工作区模型”当作当前主线。
- 不优先做通用文件管理器、最小编辑器和保存后重新执行。
- 不把任务中心升级为重型、长期持久化的任务系统。
- 不把产品路线继续往轻量 IDE 推进。

### 重要约束

- Go 工具的本地执行不依赖外部 Go 环境，因为执行逻辑在宿主编译时已经通过桥接闭包接入。
- Go 环境当前只影响三类能力：远程执行前的单工具构建、Go 单工具导出、构建缓存准备。
- 当用户选择 `<无 SDK>` 时，宿主不会再自动回退到 PATH 或已发现的 Go，可见影响通过底部状态栏的 Go 环境状态指示器提示。
- Python 工具的本地执行依赖宿主管理的托管虚拟环境；若基础 Python 缺失、工具环境未创建、缺少 pip 或动态扫描依赖未就绪，本地运行会被阻断并提示用户去配置。
- Rust 工具的本地执行优先使用随宿主打包的本地产物；如果当前处于源码工作区且没有打包产物，宿主会基于当前选中的 Rust / Zig 环境现场构建宿主平台产物。
- Rust 环境当前影响 Rust 工具的本机现场构建、远程执行前的单工具构建、Rust 单工具导出与构建缓存准备；不影响 Go/Python 工具的本地执行模型。
- Rust 环境管理采用“Rust 环境目录 + Zig SDK + 派生能力补齐”模型，而不是让用户分别选择 `cargo`、`rustup`、`rustc`、`cargo-zigbuild` 四个二进制。
- `cargo-zigbuild` 与常用 Rust targets 都视为当前 Rust 环境的派生能力；若当前激活的是系统 Rust，宿主默认不再直接替用户补齐这两类能力。
- 工作区内置工具不进入工具规格、本地/远程执行、导出和构建缓存链路；它们是桌面宿主直接提供的即时页面能力。
- 远程执行后的结果回收属于宿主编排能力，不要求每个工具自己实现下载逻辑。
- 轻量执行历史只服务于“刚执行完之后补一步操作”，不演进成网站式任务后台。

## 4. 代码真相源

- 宿主入口：`app/main.go`
- 宿主 API 与 bootstrap：`app/app.go`
- 执行编排：`app/execution.go`
- Rust 本地执行入口：`app/rust_tools.go`
- SSH 存储：`app/internal/ssh/`
- 远程执行器：`app/internal/runtime/`
- 构建与单工具产物准备：`app/internal/builder/`
- Rust 工具链与环境管理：`app/internal/toolchain/`
- 前端工作台：`app/frontend/src/components/`
- 工具规格与清单：`libs/core/toolspec/`、`libs/catalog/builtin/`

## 5. 当前主要问题

本轮已把可见问题统一收口到 [ISSUES_AND_REMEDIATION_PLAN.md](./ISSUES_AND_REMEDIATION_PLAN.md)，不再把问题列表散落在 README、计划稿和阶段总结里。

问题大类如下：

- 安全问题：归档解压路径穿越、SSH host key 校验缺失。
- 功能缺口：SSH keyPath 没有真正接入测试与远程执行。
- 状态流问题：新建 SSH 保存后的页签状态、远程任务取消清理、启动期错误兜底。
- 工程问题：Python 临时脚本并发冲突、窗口状态保存回退不足、构建脚本错误处理粗糙。
- 体验问题：远程路径参数仍默认走本地选择器、部分设置项死角、帮助文案与实际快捷键不一致，以及远程结果历史补下载仍可继续补位。
- 文档问题：旧版方案、旧路径、旧阶段结论混入当前文档。
