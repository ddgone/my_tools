# 窗口状态持久化：窗口化尺寸、最大化状态与全屏状态独立记忆

我们决定在 `app.json` 中维持单一 `window` 段（`width/height/x/y/maximised/fullscreen`），但强制一个不变式：**`width/height/x/y` 永远只存储窗口化（既非最大化也非全屏）时的几何值**，最大化或全屏时这些字段绝对不直接采样写盘。

## 背景

桌面宿主需要跨会话记忆窗口的尺寸、位置、最大化状态与全屏状态。此前实现存在四个问题：

1. **首次状态采样竞态**：前端启动早期就响应 `resize` 保存，可能把尚未稳定的默认窗口几何写入 config。
2. **恢复职责分裂**：前端负责恢复、Go 侧只负责初始尺寸，导致启动阶段窗口可能先出现在错误位置再跳转。
3. **多显示器坐标误判**：Windows 左侧或上方副屏会产生负坐标；旧实现对负坐标做了错误短路，导致拖到副屏后只要 resize 就会被误判为“离屏”，随后自动居中。
4. **Wails 原生位置语义不一致**：不同平台的 `WindowGetPosition/WindowSetPosition` 并不都使用统一的全局桌面坐标，macOS 上尤其会以当前屏幕可视区域为参考，导致跨屏恢复不可靠。

## 决策

### 不变式

`app.json` 中 `window.width/height/x/y` 的语义固定为"上一次窗口化时的几何"，不与最大化状态或全屏状态混淆。`maximised` 与 `fullscreen` 是两个正交布尔标记。写入时守卫：当前处于最大化或全屏时，不更新 `width/height/x/y`，而是沿用最近一次窗口化几何。

### 启动冷却期

前端 `onMounted` 后 2 秒内不响应保存请求，给 Go 侧 `OnDomReady` 恢复窗口状态留下稳定窗口；前端在冷却期内只做状态同步，不写盘。

### Go 侧统一恢复与关闭兜底

Go 侧在 `OnDomReady` 中统一恢复窗口化几何、最大化状态与全屏状态；在 `OnBeforeClose` 中同步采样当前窗口状态并写盘，避免只靠前端定时器兜底。

### 显示器校验

恢复窗口位置前，检查保存的**窗口矩形**是否与任意已连接显示器存在足够可见交集。若完全不可见，则回退到窗口居中。Windows 和 macOS 均使用原生显示器矩形；不再把负坐标直接视为离屏。

### 原生全局坐标

Windows 与 macOS 的跨屏恢复不再依赖 Wails runtime 的相对位置 API，而是通过宿主平台的原生窗口句柄/上下文读取和设置**全局桌面坐标**。这保证“关闭时在哪块屏幕、下次仍回到哪块屏幕”的行为在多显示器下可预期。

### 为什么不做两套完整对象

评估过方案 A（单套字段 + unmaximised 重复字段）和方案 B（`windowed` + `maximisedState` 两个完整对象），最终选择方案 C（只存窗口化 + 布尔）。理由：

- 最大化时的精确几何（`WindowGetPosition` 返回值）对恢复无意义——Windows 自己会 clamp 最大化窗口到正确位置
- 字段数翻倍增加维护负担和 config 可读性
- 不变式清晰：`width/height/x/y` 就是"下次取消最大化时恢复到的尺寸和位置"

## 后果

- 前端只负责观察状态变化并触发防抖持久化，不再自行恢复窗口位置
- Go 侧负责统一恢复与关闭前兜底保存，避免系统关闭按钮绕过前端逻辑
- `fullscreen` 成为正式持久化字段，且语义上与 `maximised` 明确区分；恢复时 `fullscreen` 优先于 `maximised`
- 多显示器恢复以“窗口矩形可见”作为判定标准，而不是左上角单点是否落屏
