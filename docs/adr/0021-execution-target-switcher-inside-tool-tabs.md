# ADR 0021: 执行目标切换器内嵌工具页签

## 日期

2026-05-29

## 状态

已采纳

## 背景

远程执行的第一版入口是 **工具详情** 右上角的一个 `远程执行` 按钮，点击后弹出 SSH 连接选择浮层。这个方案在功能上可用，但很快暴露出三个问题：

1. **安全语义过轻**：远程执行、连接选择和后续权限策略被压缩在一个按钮后面，用户难以在执行前看清"当前页签要在哪里运行"。
2. **状态承载不足**：弹层适合一次性点击，不适合承载"记住上次连接"、未来的 sudo 策略、工作目录和远程运行时等持续配置。
3. **视觉语义断裂**：虽然项目已经有 **本地执行目标** 和 **远程执行目标** 的领域语言，但工作区内没有一个显式、稳定的 UI 位置持续表达当前页签的执行目标。

同时，项目已经采纳 **单页工作台** 与 **工具页签** 范式；新的远程执行设计应继续复用页签工作区，而不是另开路由或弹窗主流程。

## 决策

**把执行目标切换器内嵌到工具页签执行区中，并将执行目标建模为页签级状态。**

具体约束如下：

1. **默认本地执行目标**：新开的 **工具页签** 默认进入 **本地执行目标**。
2. **手动切换远程执行目标**：只有用户显式操作 **执行目标切换器**，当前页签才会进入 **远程执行目标**；系统不主动帮用户切回本地。
3. **页签级记忆**：当前页签分别记住本地与远程两套执行配置；用户在本地和远程之间切换时，各自恢复之前的填写结果。
4. **远程环境选择区前置**：切到远程执行目标后，在 **工具详情** 与 **结构化表单** 之间显示 **远程环境选择区**，用于选择 SSH 连接，并为未来的详细远程配置预留位置。
5. **远程标识统一表达**：在 **工具页签**、工作区标题和 **侧边栏** 当前工具节点上，用统一的 **远程标识** 提示当前页签正处于远程执行目标。
6. **模式标识局部切换**：远程执行目标使用独立的局部 **模式标识**，通过图标、文案和轻量模式色共同提示当前页签处于远程执行目标；它只影响当前激活工具页签及其对应工具节点，不把整棵工具树或整个活动栏整体换色。

## 放弃的方案

- **方案 A: 保持一个远程执行按钮 + 浮层** — 轻量，但无法承载持续配置，也难以建立稳定的安全语义。
- **方案 B: 为远程执行单独开新页面/新路由** — 会割裂现有 **单页工作台** 范式，也不符合工具与 SSH 在同一工作区内协作的方向。
- **方案 C: 做成全局级本地/远程切换** — 实现简单，但会污染其他工具页签，且容易让用户误以为整个桌面宿主都已进入远程模式。

## 影响

- **正面**：远程执行从"一次性按钮动作"升级为工作区内显式可见的执行目标状态，安全感和可解释性更强。
- **正面**：为未来补充 sudo、工作目录、免密提权、远程运行时检测等配置留出了稳定位置。
- **正面**：本地与远程执行目标共享同一工具页签结构，避免重新发明另一套页面范式。
- **代价**：`workspace store` 需要从单套参数状态演进为按执行目标分开的页签状态。
- **代价**：工作区多个视觉模块需要支持工作台级 **界面主题** token，以及执行相关区域的本地/远程 **模式标识** token。
