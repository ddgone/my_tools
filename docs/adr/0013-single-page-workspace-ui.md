# ADR 0013: 单页工作台 UI 范式

## 日期

2026-05-25

## 状态

已采纳

## 背景

项目初期（Phase 0-1）采用 Vue Router 双页面模式：

- `/` → `HomeView`（工具浏览）
- `/execute/:toolId` → `ExecuteView`（执行操作）

用户通过路由跳转在"浏览"和"执行"之间切换，两个页面各自独立布局。

这种模式在评估阶段被明确指出不符合产品愿景：

1. 更像"展示用看板"，而非专业桌面工具
2. 与 Postman、IDEA 等专业桌面工具的体验范式不一致
3. 路由跳转打断用户操作流，无法并行查看多个工具
4. 侧边栏工具树和主工作区被割裂到两个路由内

## 决策

**采用单页工作台范式**：移除 Vue Router，以 IDE 风格组件树替代。

核心布局：

```
┌─────────────────────────────────────────────────────────┐
│ HEADER: 全局导航                                         │
├────────────┬────────────────────────────────────────────┤
│ SIDEBAR    │ TAB BAR + 主工作区（上下分栏）               │
│ 分类工具树  │  ┌ 工具详情 + 参数配置 ──────────────────┐  │
│            │  ├ 执行终端（始终可见）───────────────────  │  │
│            │  └───────────────────────────────────────  │  │
├────────────┴────────────────────────────────────────────┤
│ FOOTER: 状态栏                                           │
└─────────────────────────────────────────────────────────┘
```

### 具体变更

1. **移除 Vue Router**：不再需要 `router/index.ts`、`createRouter`、`createWebHashHistory`
2. **移除页面路由文件**：`HomeView.vue` 和 `ExecuteView.vue` 被拆解为一组独立组件
3. **新增 `WorkspaceLayout.vue`** 作为全局布局壳
4. **新增组件矩阵**：
   - `AppHeader.vue` — 顶部导航栏（Logo、搜索、SSH/导出/任务/设置入口）
   - `ToolSidebar.vue` — 左侧工具分类树 + 搜索 + 底部视图切换
   - `WorkspaceTabs.vue` — 工具页签栏 + 活动工具工作区
   - `ParameterPanel.vue` — 三模式参数配置区（可视化表单 / 命令行 / 工具说明）
   - `ExecutionTerminal.vue` — 始终可见的执行日志终端
   - `StatusBar.vue` — 底部状态栏
5. **引入 workspace store**（Pinia）管理多页签状态：打开的工具列表、活动工具 ID、每个工具的独立参数状态

### 放弃的方案

- **方案 B: 双页面 + 共享侧边栏** — 在 HomeView 和 ExecuteView 之间用 slot 或 teleport 共享侧边栏。问题：仍需要路由跳转，且代码复用笨拙。
- **方案 C: 嵌套路由** — 用 `children` 路由在 `/workspace` 下嵌套子路由。问题：本质上还是路由跳转范式，工具并行打开无法实现。

## 影响

- **正面**：产品体验从"展示用看板"升级为"专业桌面工作台"，与行业标杆对齐
- **正面**：多页签架构天然支持未来的"并行执行多工具"场景
- **正面**：单页工作台为后续 SSH 连接管理、导出中心等面板在同一窗口中打开铺平了路
- **代价**：需要重写当前所有前端视图代码，但当前代码量总计约 630 行（两个 View），迁移成本可控
- **代价**：需要新增 workspace store 管理多页签状态
