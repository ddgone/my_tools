# ADR 0016: SSH 连接管理与工具享有同等 Tab 页体验

## 日期

2026-05-26

## 状态

已采纳

## 背景

SSH 连接管理的最初实现有三个问题：

1. **Tab 顺序固定**：SSH 页签总是排在所有工具页签之后，不符合按打开时间排序的直觉。
2. **表单靠左拥挤**：SSH 编辑表单靠左侧对齐，与工具详情页的全宽居中风格不统一，视觉割裂。
3. **密码不可见**：编辑已有连接时密码字段始终为空，因为列表接口 `List()` 主动清空了 `Password` 字段，且前端额外做了一次清空。

更深层的问题在于，之前的方案把 SSH 面板作为右侧主工作区的"替代视图"——当选中 SSH 连接时，整个右侧区域被替换为 SSH 面板，与工具页签系统是互斥关系。这导致用户无法同时看到工具页签和 SSH 编辑界面，体验割裂。

## 决策

**SSH 连接管理与工具享有同等 Tab 页体验**：

1. **统一 Tab 系统**：`workspace store` 新增 `sshTabs` 和 `unifiedTabs` computed，将工具页签和 SSH 页签合并为按 `openedAt` 时间戳排序的统一列表，模板用单套 `v-for` 渲染。
2. **工具风格表单**：SSH 表单采用与工具详情页一致的 `max-w-xl mx-auto` 居中布局，标题栏、表单区、底部操作栏与工具页面共享同一套视觉语言。
3. **独立打开/关闭**：从侧边栏点击 SSH 连接或新建按钮时，调用 `openSSHEdit` / `openSSHNew` 在 Tab 系统内新增页签，不影响已有的工具页签。
4. **凭据安全加载**：后端新增 `GetSSHConnection(id)` 接口返回完整凭据（含密码），仅在打开编辑页时调用。列表接口 `List()` 仍然只返回脱敏后的元数据。
5. **相互切换**：`openTool` 和 SSH 开页方法都负责重置对方的 `activeIndex = -1`，确保 `activeTabType` computed 正确判断当前激活的是工具还是 SSH。

### 放弃的方案

- **方案 A: SSH 面板独立占据右侧** — 第一版就是这样实现的。问题：与工具页签互斥，无法并行查看，切换时体验割裂。
- **方案 B: SSH 表单以弹窗（Modal）形式打开** — 问题：弹窗遮挡主工作区，编辑大型表单时操作局促，且与"桌面工具"的沉浸式体验目标冲突。
- **方案 C: SSH 表单放在侧边栏内** — 问题：侧边栏宽度有限（180-480px），无法承载完整表单，操作不便。

## 影响

- **正面**：SSH 连接管理与工具管理共享同一套交互范式，学习成本降低
- **正面**：用户可同时打开多个工具页签和多个 SSH 编辑页签，自由切换
- **正面**：表单居中全宽，视觉统一
- **正面**：密码可正常显示和编辑
- **代价**：workspace store 增加了 `SSHTabState`、`unifiedTabs`、`activateUnifiedTab`、`closeUnifiedTab` 等抽象，复杂度有所增加
- **代价**：后端新增 `GetSSHConnection` 暴露凭据接口，需注意仅在前端需要编辑时才调用
