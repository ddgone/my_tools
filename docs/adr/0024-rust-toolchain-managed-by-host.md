# ADR 0024: Rust 工具链由宿主管理，并建模为 Rust 环境目录 + Zig SDK + 派生能力补齐

## 日期

2026-06-14

## 状态

已采纳

## 背景

项目已经引入首个 Rust 工具 `las_voxelizer`，并且 Rust 工具不再只是“实验性语言分支”，而是正式进入：

- 本地执行
- 远程执行
- 单工具导出
- 产物中心矩阵构建

在此之前，Rust 相关能力存在三个明显问题：

1. **用户心智不统一**：如果直接让用户手动选择 `cargo`、`rustup`、`rustc`、`cargo-zigbuild`，会把本质上属于同一 Rust 环境目录的东西拆散。
2. **跨平台构建链路不完整**：Rust 的跨平台构建同时依赖 `rustup target add`、`cargo-zigbuild` 和 Zig，无法简单复用 Go 或 Python 的环境模型。
3. **系统环境风险过高**：如果自动探测优先命中系统 Rust，再直接补齐 `cargo-zigbuild` 或 targets，宿主就有机会无提示修改 `~/.cargo` / `~/.rustup`。

同时，项目已经接受几个更高层的约束：

- 桌面宿主要对用户暴露“能完成工作”的环境模型，而不是语言工具链的内部零件清单。
- 远程执行与导出前的后台产物准备统一由宿主负责，而不是把构建责任推给用户或远端机器。
- 运行时目录下的 `toolchains/` 已经是托管 Go / Python 相关环境资产的既有落点，Rust 不应另起一套完全不同的管理口径。

## 决策

**Rust 工具链由桌面宿主管理，并采用“Rust 环境目录 + Zig SDK + 派生能力补齐”的模型。**

具体约束如下：

1. **Rust 主对象是环境目录**：设置页中 Rust 选择的是可解析出 `cargo` / `rustc` / `rustup` 的 Rust 环境目录，而不是单个二进制路径。
2. **Zig 独立建模**：Zig 作为独立 SDK 与 Rust 环境并列选择，但只在 Rust 交叉编译链路中发挥作用。
3. **`cargo-zigbuild` 与 targets 作为派生能力**：它们依附当前 Rust 环境检测与补齐，不作为单独主 SDK 暴露。
4. **支持组件化托管安装**：当前允许下载 Rust、下载 Zig、或下载 Rust + Zig；多个托管版本允许共存。
5. **自动探测优先托管 Rust**：若同时存在托管 Rust 与系统 Rust，自动探测优先托管目录，避免用户在无感知下操作系统环境。
6. **系统 Rust 默认受保护**：宿主默认不再直接替系统 Rust 自动补齐 `cargo-zigbuild` 或常用 targets。
7. **构建链路统一复用**：Rust 工具的本地现场构建、远程执行前构建、单工具导出和产物中心矩阵，统一复用宿主的 Rust builder。

## 放弃的方案

- **方案 A: 直接暴露 `cargo` / `rustup` / `rustc` / `cargo-zigbuild` 四个选择框**  
  灵活但不符合用户心智，也会把同一环境目录拆成互相可能不一致的零件。

- **方案 B: 完全依赖系统 Rust，不做托管安装**  
  实现最省事，但无法提供稳定的下载、切换、多版本共存和环境隔离，也无法避免系统 Rust 被误修改。

- **方案 C: 只托管 Rust，不托管 Zig**  
  交叉编译体验不完整，仍然要求用户自己处理 Zig 安装与路径选择，和当前“宿主管理构建前置条件”的方向不一致。

## 影响

- **正面**：Rust 环境模型与用户目标一致，设置页不再暴露语言工具链内部零件。
- **正面**：Rust 工具的本地执行、远程执行、导出与产物中心构建使用同一套环境解析与构建链路。
- **正面**：托管 Rust / Zig 支持多版本共存、下载回退和运行时目录隔离。
- **正面**：通过“系统 Rust 受保护 + 自动探测优先托管 Rust”降低误伤用户现有环境的风险。
- **代价**：宿主需要维护一整套 Rust 环境发现、安装、状态、补齐和任务反馈逻辑，复杂度高于 Go / Python 当前模型。
- **代价**：Rust 工具的本地执行语义与 Go / Python 不同，需要额外文档明确说明。

## 当前适用范围

当前这条决策适用于：

- `kind: rust` 的普通工具
- Rust 工具的本地执行、本地导出、远程执行前构建和产物中心矩阵构建
- 设置页中的 Rust / Zig 环境管理

当前不适用于：

- 工作区内置工具
- 需要在远端现场编译 Rust 源码的场景
- 把整套 Rust 工具链打进单工具导出包的场景
