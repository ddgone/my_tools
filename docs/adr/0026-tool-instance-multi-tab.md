# ADR 0026: 工具实例支持同工具多页签

## 日期
2026-07-07

## 状态
已接受

## 背景

当前工具页签模型规定每个工具只能在工作区中打开一个页签。`openTool()` 通过 `toolId` 去重，`tabId` 固定为 `tool_${tool.id}`，这导致用户无法同时以不同参数组合、不同执行目标运行同一个工具。

用户需要在同一工具上并行执行多组参数（例如同一工具分别跑"上海样本"和"北京样本"），或在本地和远程同时验证同一工具。现有模型迫使用户串行执行或手动切换参数，效率低下。

## 决策

引入 **工具实例**（Tool Instance）概念：

1. 一个 **工具** 在工作区中可以拥有多个 **工具实例**，每个实例对应一个页签。
2. 默认给每个工具创建一个 **主实例**（`instanceId = toolId`），点击工具树中的工具激活主实例。
3. 用户通过页签右键菜单"复制实例"创建完全隔离的副本。副本继承当前实例的全部参数配置、执行目标和终端状态，但不继承运行中的任务绑定。
4. 每个实例拥有独立的 `instanceId`，执行任务通过 `instanceId` 归属到具体实例，不再通过 `toolId + target` 猜测。
5. 不同实例之间参数配置、执行目标、终端状态和执行历史完全独立。
6. 关闭实例时自动保存快照到 `instanceSnapshots`，可通过最近使用列表恢复。

### 实例标识

- 主实例：`instanceId = toolId`（保持与现有固定标签机制的兼容）
- 副本实例：`instanceId = toolId + '_' + nanoid(8)`（保证唯一性和短小可读）

### 执行归属

- `ExecutionRequest` 和 `ExecutionTask` 均增加 `instanceId` 字段
- 前端任务归属从 `activeTabTaskId = find(tasks, toolId + target)` 改为 `activeTabTaskId = find(tasks, instanceId)`

### 实例生命周期

| 阶段 | 行为 |
|---|---|
| 创建 | 工具树点击或"复制实例"右键菜单 |
| 运行 | 每实例独立发起执行，任务携带 `instanceId` |
| 关闭（无运行中任务） | 存快照，移除页签 |
| 关闭（有运行中任务） | 弹确认框：取消任务并关闭 / 转后台运行并关闭 |
| 恢复 | 从最近使用或固定标签恢复，加载快照 |
| 淘汰 | 快照按 `historyRetention` 做 LRU 淘汰；固定标签的快照永久保留 |

## 替代方案

### 方案 A：在每个页签内支持多任务列表

在同一个工具页签内提供任务队列/列表，允许用户在一个页签内启动多个任务。

**放弃原因**：终端区、取消按钮、下载按钮都要变成列表视图，UI 复杂度骤增。用户心智上习惯"一个 Tab = 一件事"。

### 方案 B：保持单实例，加"任务模板"功能

允许用户保存多组参数为模板，但每次只能跑一个。

**放弃原因**：不满足并行执行的核心诉求。

### 方案 C：按"任务组"组织

引入"任务组"概念，一个任务组同时跑多组参数。

**放弃原因**：过度抽象，当前没有批量编排需求，且任务组与工具页签的 UI 关系不清晰。

## 影响

- **前端**：`workspace.ts` 的 `ToolTabState`、`openTool`、`recordUsage`、`persistedToolStates` 及 `pinnedTabs` 格式需要重构。
- **后端**：`ExecutionRequest`、`RemoteExecRequest`、`ExecutionTask` 增加 `instanceId` 字段。执行管理器透传该字段。
- **协议**：Wails 事件 `task:update` 携带的 `ExecutionTask` 新增字段，前端需同步类型定义。
- **CONTEXT.md**：新增"工具实例"术语，更新"工具页签"定义。
