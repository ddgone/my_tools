# 使用本地统一调度加 SSH 透传的远程执行模型

远程执行采用“本地统一调度 + SSH 透传”模型：桌面宿主在本地决定执行目标、准备工具专属产物、上传到远端、触发执行并在完成后清理远端临时产物，同时在本地保留编译缓存以复用后续执行与导出。我们不采用长期驻留的远端代理，因为当前目标是让同一工具天然支持本地执行、远程执行与后续导出三条路径，并尽量把复杂度收敛在本地宿主和统一构建能力中。

当前实现进一步明确为：远程执行不能直接把参数串当成命令运行，而必须先解析远端 OS/Arch，生成对应的工具专属产物，上传到远端临时目录后再以该产物作为命令入口执行。

在开发态，这条链路依赖本地可发现的 Go 工具链来构建 Go 工具专属产物；因此桌面宿主需要显式执行“Go 工具链发现”，而不能仅假设 `go` 已经在进程 PATH 中可见。
