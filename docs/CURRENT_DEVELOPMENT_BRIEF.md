# 当前开发简报

本文档把当前已经确认的产品边界和首个开发包收成一份可直接执行的实现简报。它不讨论长期愿景，只回答“现在该做什么、先不做什么、做到什么算完成”。

## 1. 当前产品边界

- 项目定位：个人桌面工具工作台，不是轻量 IDE，不是网站式任务后台。
- 主用途：拿起来就运行工具；必要时切到远程；执行后看结果；需要时导出工具或把远端结果手动拉回本地。
- 历史定位：只做轻量执行历史，用来补看日志和补一次下载，不做长期任务运营系统。
- SSH 终端定位：独立辅助能力，不先和工具页签状态深度耦合。

## 2. 已定实现原则

- 结果下载采用“执行后探测 + 手动下载”，不做自动下载。
- 当前工具页签是结果下载的主入口；轻量历史只是补充入口。
- 只有显式输出文件或输出目录的工具，才参与结果探测和结果下载。
- 工具规格先用约定启发式跑起来，再给少量特例补显式覆盖。
- 远程模式下的路径浏览最终应切到远程路径选择器，但这不是当前第一包的阻塞项。

## 3. 当前已完成开发包

当前已经完成一轮可直接使用的远程结果闭环，包含：

1. 基于启发式约定的远程结果探测。
2. 远程任务结束后的结果可用性判断。
3. 当前工具页签里的“下载输出结果”主入口。
4. 单文件直接下载、目录远端打包后下载。
5. 顶栏下载入口、进行中下载抽屉、下载完成自动打开目录。
6. 目录下载的真实大小探测与真实百分比。

这意味着项目已经第一次具备“远程执行 -> 探测结果 -> 手动下载 -> 本地打开目录”的完整闭环。

## 4. 当前下一开发包

下一步不继续扩张下载系统，而是补齐远程模式下最直接的体验缺口：

1. 实现参数级远程路径选择器。
2. 让远程模式下的浏览按钮看到远端目录，而不是本地文件选择器。
3. 保持本地接收路径仍走本地选择器，不把两侧语义混在一起。
4. 只为少量启发式不准的工具补最小语义覆盖，不重做整套 schema。

这一包做完后，远程执行的准备阶段和执行后的结果阶段才算真正连起来。

## 5. 结果下载的当前约定

### 宿主如何判断结果位置

- 第一层启发式：
  - `argKey: output`
  - `key: output`
  - `key: outputDir`
- 第二层显式覆盖：
  - 只给少量启发式不准的工具使用
  - 不要求所有 manifest 一次性改写

### 下载行为

- 远程任务结束后，宿主探测输出路径是否存在。
- 若输出是文件，直接下载。
- 若输出是目录，在远端打包后下载。
- 若输出不存在，只给出明确提示，不反向改写任务成败。
- 若任务失败但输出仍存在，仍允许手动下载。

### 入口位置

- 主入口：当前工具页签。
- 补充入口：轻量执行历史。

## 6. 当前不做

- 不做自动下载。
- 不做通用 FTP / SFTP 客户端。
- 不做通用远端文件管理器。
- 不做工具工作区模型。
- 不做编辑器和保存后重新执行。
- 不做重型任务中心。
- 不把 SSH 终端内嵌到工具页签里。
- 不为了结果下载继续复杂化下载中心 UI。

## 9. 完成标准

当前这轮结果闭环已经完成，完成标志是：

- 远程任务结束后，宿主能判断是否存在可下载结果。
- 当前工具页签能在合适时机显示“下载结果”入口。
- 用户能把单文件或输出目录从远端手动拉回本地。
- 顶栏能看到进行中的下载任务并查看下载状态。
- 结果缺失、下载失败、失败任务仍有结果等边界情况都有明确反馈。

下一开发包的完成标志是：

- 远程模式下点击路径参数的浏览按钮时，能看到远端目录或文件。
- 本地接收路径仍然走本地选择器。
- 至少覆盖输入目录、输出目录、输出文件三种参数。
- 启发式不准的历史工具可以通过最小显式覆盖修正行为。
