# 当前开发简报

本文档把当前已经确认的产品边界和首个开发包收成一份可直接执行的实现简报。它不讨论长期愿景，只回答“现在该做什么、先不做什么、做到什么算完成”。

## 1. 当前产品边界

- 项目定位：个人桌面工具工作台，不是轻量 IDE，不是网站式任务后台。
- 主用途：拿起来就运行工具；必要时切到远程；执行后看结果；需要时导出工具或把远端结果手动拉回本地。
- 历史定位：只做轻量执行历史，用来补看日志和补一次下载，不做长期任务运营系统。
- SSH 终端定位：独立辅助能力，不先和工具页签状态深度耦合。

## 2. 已定实现原则

- 结果下载采用“执行后探测 + 手动下载”，不做自动下载。
- 当前工具页签是结果下载的主入口；轻量历史只是补充入口。
- 只有显式输出文件或输出目录的工具，才参与结果探测和结果下载。
- 工具规格先用约定启发式跑起来，再给少量特例补显式覆盖。
- 远程模式下的路径浏览最终应切到远程路径选择器，但这不是当前第一包的阻塞项。

## 3. 当前首个开发包

推荐按下面顺序直接开工：

1. 恢复 SSH host key 基本校验。
2. 打通 SSH 密钥认证全链路。
3. 定义远程结果探测的最小约定。
4. 实现后端远程结果探测与手动下载。
5. 接通当前工具页签里的“下载结果”入口。

这五步做完后，项目会第一次具备完整的远程结果闭环。

## 4. 结果下载的当前约定

### 宿主如何判断结果位置

- 第一层启发式：
  - `argKey: output`
  - `key: output`
  - `key: outputDir`
- 第二层显式覆盖：
  - 只给少量启发式不准的工具使用
  - 不要求所有 manifest 一次性改写

### 下载行为

- 远程任务结束后，宿主探测输出路径是否存在。
- 若输出是文件，直接下载。
- 若输出是目录，在远端打包后下载。
- 若输出不存在，只给出明确提示，不反向改写任务成败。
- 若任务失败但输出仍存在，仍允许手动下载。

### 入口位置

- 主入口：当前工具页签。
- 补充入口：轻量执行历史。

## 5. 当前不做

- 不做自动下载。
- 不做通用 FTP / SFTP 客户端。
- 不做通用远端文件管理器。
- 不做工具工作区模型。
- 不做编辑器和保存后重新执行。
- 不做重型任务中心。
- 不把 SSH 终端内嵌到工具页签里。

## 7. 完成标准

当下面条件同时成立，就可以认为当前第一包完成：

- SSH 测试连接与正式执行都不再绕过 host key 校验。
- SSH 连接可通过密码或密钥完成测试与远程执行。
- 远程任务结束后，宿主能判断是否存在可下载结果。
- 当前工具页签能在合适时机显示“下载结果”入口。
- 用户能把单文件或输出目录从远端手动拉回本地。
- 结果缺失、下载失败、失败任务仍有结果等边界情况都有明确反馈。

## 8. 回归要求

至少执行：

```bash
go test ./...
go vet ./...
cd app/frontend && npm run lint
cd app/frontend && npm run typecheck
```

同时做手工回归：

- 未知主机、已知主机、指纹变化三种 SSH 场景。
- 密码认证与密钥认证两条链路。
- 远程结果为文件、目录、不存在三种场景。
- 成功任务下载、失败任务补下载、下载失败提示三种场景。
