# 配置持久化统一说明

本文记录当前仓库里“配置到底存在哪”的真实现状，以及后续把前后端配置统一到文件配置时的迁移思路。

这不是已经生效的架构决策，只是后续改造的设计说明。

## 当前现状

- `build/runtime/config/app.json`
  - 当前主要承接宿主级配置。
  - 已稳定接入的是窗口状态 `window`、导出最近目录 `export.lastDirectory` 与 Go 环境配置 `go`。
  - 文件位置由运行时目录布局决定，开发态使用仓库内 `build/runtime/config/`，安装态回退到用户目录。

- `build/runtime/config/ssh_connections.json`
  - 由后端 SSH store 负责。
  - 属于宿主可变运行时配置的一部分。

- 前端 `localStorage`
  - 当前承接工作台偏好和会话增强状态。
  - 已包含：
    - 收藏工具
    - 最近使用
    - 参数历史
    - 工具参数快照
    - 固定标签
    - 标签顺序
    - 部分前端设置项

## 当前 Go 环境配置的落点

- Go 环境当前已经稳定落在后端配置文件中，而不是前端 `localStorage`。
- 目前落在 `app.json` 的 `go` 块字段包括：
  - `selectedBinary`
  - `knownBinaries`
  - `lastInstallDirectory`
  - `disabled`
- 这样处理的原因是：
  - Go 环境会直接影响后端 builder、远程执行和导出链路；
  - 它不是纯前端偏好，而是宿主运行时能力的一部分；
  - 它需要在前端初始化之前就能被后端 API 稳定读取。

## 当前固定标签的落点

- 固定标签当前继续写在前端本地持久化中。
- 相关键包括：
  - `fire-salamander:pinned-tabs`
  - `fire-salamander:tab-order`
- 这样处理的原因是：
  - 当前前端工作台状态本来就主要由 `workspace` store 统一管理；
  - 固定标签属于工作台交互偏好，不是宿主启动前必须读取的配置；
  - 现阶段强行把前端状态塞进 `app.json`，会引入前后端桥接、配置 schema、迁移兼容三件事一起改，改动面过大。

## 为什么暂时不直接写进 `app.json`

- `app.json` 当前的实际稳定职责主要还是宿主窗口、运行时宿主配置和少量已稳定接入的运行时能力配置。
- Go 环境已经有独立配置模型和成套的读写 API，但工作台偏好整体仍未统一进文件配置。
- 如果只为了固定标签临时往 `app.json` 里补字段，会出现：
  - 宿主配置与工作台配置边界变糊；
  - 前端和后端各自维护一半配置模型；
  - 后续真正做“统一配置文件”时还要再迁移一遍。

## 后续建议的统一方向

- 目标不是“把前端配置硬塞进现有 `app.json`”，而是建立一个明确的统一配置模型。
- 建议后续改成：
  - 后端维护单一配置服务；
  - 配置文件继续放在运行时配置目录；
  - 前端通过 Wails API 读取和保存工作台配置；
  - 前端 `localStorage` 只保留真正适合纯本地缓存的临时状态，或逐步完全退出。

## 建议的配置分层

- `app`
  - 版本、语言等宿主元信息。

- `window`
  - 窗口位置、尺寸、最大化、全屏。

- `ui`
  - 主题、快捷键展示方式等界面偏好。

- `workspace`
  - 收藏工具
  - 最近使用
  - 参数历史
  - 工具参数快照
  - 固定标签
  - 标签顺序

- `execution`
  - 默认 Python
  - 历史保留条数
  - 与执行行为直接相关的用户级默认项

- `go`
  - 当前选中的 Go 二进制
  - 已知 Go 二进制列表
  - 最近安装目录
  - 是否显式禁用当前 Go 环境

## 建议的迁移步骤

1. 先在 Go 侧定义统一配置结构，而不是只追加零散字段。
2. 暴露 `GetAppConfig` / `SaveAppConfig` 一类的桥接 API。
3. 前端 `workspace` store 改为优先读写后端配置。
4. 首次启动时从旧 `localStorage` 迁移一次数据到文件配置。
5. 迁移完成并验证稳定后，再决定是否彻底移除旧 `localStorage` 键。

## 迁移时的注意点

- 窗口状态仍然要保持“宿主启动前可读取”的能力，不能被前端初始化顺序反向卡住。
- 配置 schema 需要明确哪些是宿主级、哪些是工作台级，避免继续混杂。
- 迁移必须做兼容读取，否则现有用户的收藏、历史和固定标签会丢失。
- 运行时目录仍应保持“开发态仓库内、安装态用户目录”的现有约束，不应回写安装镜像目录。
