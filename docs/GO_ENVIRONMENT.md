# Go 环境使用说明

本文档只说明当前已经落地的 Go 环境能力，以及它在桌面宿主中的真实影响范围。

## 1. 先说结论

- Go 工具的本地执行不依赖额外安装的 Go 环境。
- Go 环境当前只影响三类能力：
  - 远程执行前的单工具构建
  - Go 单工具导出
  - 构建缓存准备
- 用户可以在系统首选项的 Go 页签里：
  - 选择本地 Go
  - 下载官方 Go SDK
  - 查看下载进度、下载速度，并可在下载中主动停止
  - 切换已检测到的 Go
  - 检查当前 Go 环境
  - 删除当前托管 Go 环境
  - 选择 `<无 SDK>` 显式禁用当前 Go 环境

## 2. 为什么本地执行不受影响

- 当前 Go 工具的本地执行不是“点运行时临时 `go build`”。
- 它直接运行桌面宿主在编译时桥接进来的执行闭包。
- 所以：
  - 本地执行能否运行，主要取决于工具是否已经正确接入宿主
  - 不取决于用户机器上是否额外配置了 Go SDK

如果你看到状态栏写着 `Go 未配置 · 仅远程/导出受影响`，意思就是：

- 本地运行仍然可用
- 远程执行、导出和构建缓存准备会被阻断

## 3. 用户能做什么

当前系统首选项里的 Go 页签支持四类操作：

### 3.1 选择本地 Go

- 选择机器上已经安装好的 `go` 可执行文件
- 校验成功后立即作为当前 Go 环境生效

### 3.2 下载官方 Go SDK

- 从官方发布源拉取当前平台可安装的稳定版列表
- 下载并解压到宿主运行时目录下的 `toolchains/`
- 用户填写的是安装基目录，实际会自动落到版本子目录，例如 `toolchains/go1.26.4/`
- 如果目标版本目录已经存在且内容可复用，宿主会直接复用，不要求整个基目录为空
- 安装完成后自动设为当前 Go 环境

### 3.3 下载任务反馈

- 下载 Go SDK 时，设置页会出现独立的下载任务卡片
- 任务卡片会显示：
  - 当前步骤
  - 当前下载项
  - 单份传输摘要，例如 `57.1 MB / 61.7 MB · 2.4 MB/s`
  - 进度条与步骤序号
- 下载中的传输摘要当前只显示一份，不会再重复渲染同一条大小/速度信息
- 如果下载卡住或用户想中止，可以直接点击 `停止`
- 停止后会取消当前任务，并清理这次下载留下的临时文件和未完成目标目录

### 3.4 检查当前 Go 环境

- 设置页提供 `检查环境`
- 检查通过时，会确认当前激活 Go 是否可解析，并展示版本与来源类型
- 如果当前没有可用 Go，会明确提示需要重新选择本地 Go 或下载 SDK

### 3.5 切换 Go 环境

- 如果系统已经检测到多个可用 Go，用户可以直接切换
- 已安装过的托管 SDK 和已选过的本地 Go 都会保留在候选列表中

### 3.6 删除当前托管 Go 环境

- 如果当前激活的是托管 Go SDK，设置页提供 `删除环境`
- 删除后会移除对应版本目录，并把配置切回剩余可用 Go 或空状态
- 如果当前激活的是本地 Go，这个删除入口不会启用

### 3.7 选择 `<无 SDK>`

- 这不是“检测失败”，而是用户主动清除当前 Go 环境
- 进入这个状态后：
  - 本地执行仍可用
  - 远程执行、Go 导出、构建缓存准备会被阻断
  - 宿主不会再自动回退到 PATH 或已发现的 Go

## 4. 默认安装到哪里

Go SDK 的默认安装路径跟运行时目录绑定。

### 开发态

- 默认放在仓库内：

```text
build/runtime/toolchains/
```

- 如果直接启动 `build/image/host/*.app`，运行时目录仍会优先回到仓库内的 `build/runtime/`

### 安装态

- 默认回退到用户目录运行时位置：

```text
~/.fire-salamander/toolchains/
```

## 5. 状态栏怎么看

底部状态栏里的 Go 状态块是当前唯一的轻量环境入口。

### 已配置

- 显示类似：

```text
Go 已就绪 · Go 1.26.3
```

- 点击可以打开 Go 设置页
- hover 会显示：
  - 当前版本
  - 实际 `go` 二进制路径
  - 当前状态说明

### 未配置

- 显示类似：

```text
Go 未配置 · 仅远程/导出受影响
```

- 点击可以直接打开 Go 设置页
- hover 会明确说明：
  - 本地运行不受影响
  - 远程执行、导出和构建缓存需要 Go 环境

## 6. 常见使用场景

### 只想本地运行 Go 工具

- 可以不配置 Go 环境
- 只要工具已经正确接入宿主，本地运行就能工作

### 想远程执行 Go 工具

- 需要先配置一个可用的 Go 环境
- 因为宿主会先为目标平台构建单工具产物，再上传到远端执行

### 想导出 Go 工具

- 需要先配置一个可用的 Go 环境
- 因为 Go 导出会走单工具构建链路

### 想临时关闭 Go 环境影响

- 可以选择 `<无 SDK>`
- 这适合你验证“没有 Go 环境时，系统应该如何表现”

## 7. 排障建议

### 状态栏显示未配置，但本地运行正常

- 这是正常现象
- 说明当前只影响远程执行、导出和构建缓存

### 已经安装过 Go SDK，但仍提示未配置

- 先检查是否误选了 `<无 SDK>`
- 再检查设置页里当前是否真的选中了某个 Go

### 下载时为什么会看到大小和速度信息

- 这是 Go SDK 下载任务的传输摘要
- 当前格式统一为：

```text
已下载大小 / 总大小 · 当前速度
```

- 如果服务端没有返回总大小，会退化为：

```text
已下载大小 · 当前速度
```

- 当前实现已经收口为只显示一份传输摘要，不会重复显示两条一模一样的下载详情

### 下载失败时怎么看

- 现在失败提示会尽量按场景分类，而不是统一显示成一个笼统错误
- 常见失败类型包括：
  - 获取 Go 版本列表失败
  - 未找到可下载的 Go 版本
  - 当前平台缺少对应安装包
  - 安装目录不可用
  - 创建下载缓存失败
  - 下载 Go SDK 失败
  - 解压 Go SDK 失败
  - Go SDK 安装不完整
- 如果安装包已经成功落盘，但最后写配置失败，任务文案也会明确提示“已安装，但保存环境配置失败”

### 远程执行或导出时报 Go 环境缺失

- 说明当前 Go 环境没有通过后端解析
- 优先重新选择一次本地 Go，或重新下载并切换到托管 SDK

### 构建脚本输出里出现 Go SDK 测试源码噪音

- 当前构建脚本已经改成只 vet 项目源码
- 若再次出现类似 `build/runtime/toolchains/.../test/...` 的输出，优先检查是否又把 `go vet ./...` 直接跑在了仓库根

## 8. 验收清单

如果你要验证这套能力是否正常，最小检查清单如下：

- 选择本地 Go 后，状态栏显示 `Go 已就绪`
- 下载官方 SDK 后，状态栏版本和路径同步更新
- 下载任务中只显示一份大小/速度摘要，且可以主动停止
- 下载失败时，任务卡片会给出更具体的失败原因
- 选择 `<无 SDK>` 后，状态栏显示 `Go 未配置 · 仅远程/导出受影响`
- 在 `<无 SDK>` 状态下，本地执行 Go 工具仍然可用
- 在 `<无 SDK>` 状态下，远程执行和 Go 导出会被阻断并引导去配置
