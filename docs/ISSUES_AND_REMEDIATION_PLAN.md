# 问题总表与分步修复计划

本文档汇总当前仍值得投入的高优先级与中优先级问题，并按“个人桌面工具工作台”的产品边界重新排序。目标不是把项目继续推向更重的平台，而是让现有主链路足够稳、够顺手，可以直接进入下一轮开发。

执行规则：

- 每个步骤只解决 1 到 2 个问题。
- 同一步内的问题必须属于同一条链路，避免边修边扩散。
- 先收口安全与稳定性，再补远程执行后的结果闭环。
- 结果下载坚持“执行后探测 + 手动下载”，不做自动下载。
- 历史只做轻量补位，不演进成重型任务系统。

## 1. 当前问题清单

| 编号 | 问题 | 等级 | 现象 |
|------|------|------|------|
| P01 | `tar.gz` 解压存在路径穿越风险 | 高 | 恶意归档可能把文件写到目标目录外 |
| P02 | SSH host key 校验被关闭 | 高 | 连接和测试都使用 `InsecureIgnoreHostKey()` |
| P03 | SSH `keyPath` 未接入远程执行 | 高 | UI 有字段，但后端实际只走密码认证 |
| P04 | 新建 SSH 连接的测试连接不支持 `keyPath` | 高 | 新建表单可填密钥，但测试按钮链路不接受 |
| P05 | 新建 SSH 保存后页签状态未回填 | 高 | 保存后仍保留“新建连接”状态，易重复保存 |
| P06 | 远程任务结束后未清理 `cancel` 状态 | 中 | 长期运行可能累积脏任务状态 |
| P07 | 工作台启动期 `hydrate()` 缺少错误兜底 | 中 | 后端异常时可能直接出现未处理拒绝 |
| P08 | Python 临时脚本写到固定临时文件名 | 中 | 并发执行同一工具时会互相覆盖 |
| P09 | 窗口状态保存依赖现有 `app.json` | 中 | 配置缺失或损坏时保存窗口状态会失败 |
| P10 | 构建脚本忽略关键错误且依赖当前目录 | 中 | 失败可能被吞掉，脚本对 cwd 很脆弱 |
| P11 | Windows 默认 Python 路径策略不稳 | 中 | 默认写成 `python3`，在 Windows 首启有风险 |
| P12 | 设置项和交互文案存在死角 | 中 | `ESC` 文案与实现不一致，部分设置项未接线 |
| P13 | 远程执行后缺少结果探测与手动下载闭环 | 高 | 执行完成后只能看日志，不能顺手拿回结果 |
| P14 | 路径参数在远程模式下仍默认走本地选择器 | 中 | 用户切到远程模式后，浏览按钮仍弹本地文件选择器 |
| P15 | 工具规格缺少远程结果探测的最小约定 | 中 | 宿主无法稳定判断哪些输出参数应参与结果回收 |
| P16 | 缺少独立 SSH 终端入口 | 中 | 有 SSH 连接管理，但没有真正可用的交互式终端 |
| P17 | 文档真相源漂移 | 高 | 旧路径、旧阶段结论、旧计划混入当前文档 |

## 2. 当前推荐执行顺序

### 已完成：远程结果闭环第一包

- 已完成问题：`P13` 的主路径
- 已完成范围：
  - `app/execution.go`
  - `app/task_result.go`
  - `app/internal/runtime/`
  - `ToolDetailPanel.vue`
  - `WorkspaceTabs.vue`
  - `AppHeader.vue`
  - `DownloadTaskDrawer.vue`
  - `downloads.ts`
- 已完成内容：
  - 远程任务结束后探测结果是否存在
  - 文件直接下载、目录远端打包后下载
  - 当前工具页签里的“下载输出结果”入口
  - 顶栏下载入口与进行中任务抽屉
  - 目录下载真实大小探测与真实百分比
- 当前判断：
  - 这条主链路已经可用，后续不需要继续把下载中心做重
  - 轻量历史补下载可以保留为后续补位项，不再作为最近一步

### Step 01: 修复归档解压安全漏洞

- 解决问题：`P01`
- 范围：`tools/go_tools/utm_extract_to_gis/`
- 目标：所有解压输出路径都必须落在目标目录内，拒绝 `..`、绝对路径和异常链接。
- 验收：构造恶意归档时返回错误，不产生越界写入。

### Step 02: 恢复 SSH 连接基本安全边界

- 解决问题：`P02`
- 范围：`app/internal/runtime/`、`app/internal/ssh/`
- 目标：移除 `InsecureIgnoreHostKey()`，补上明确的 host key 校验策略和错误提示。
- 验收：未知主机、指纹不匹配、正常匹配三种情况都有明确结果。

### Step 03: 打通 SSH 密钥认证全链路

- 解决问题：`P03`、`P04`
- 范围：`app/app.go`、`app/internal/ssh/`、`app/internal/runtime/`、`SSHDetailPanel.vue`
- 目标：`keyPath` 能同时用于保存、测试连接和正式远程执行；密码认证与密钥认证共享一致的前后端模型。
- 验收：新建连接和已保存连接都能分别用密码或密钥完成测试与执行。

### Step 04: 修复 SSH 新建连接状态回填

- 解决问题：`P05`
- 范围：`workspace.ts`、`WorkspaceTabs.vue`、`SSHDetailPanel.vue`
- 目标：新建连接保存成功后，当前页签立即切换为“已保存连接”的真实状态，不再残留草稿身份。
- 验收：同一页签内可继续编辑、测试、删除，不再重复创建连接。

### Step 05: 收口任务生命周期与启动期错误兜底

- 解决问题：`P06`、`P07`
- 范围：`app/execution.go`、`WorkspaceLayout.vue`
- 目标：远程任务结束后清理 `cancel` 状态；启动期任何 bootstrap / hydrate 失败都能被前端接住并给出可恢复提示。
- 验收：任务结束后内部状态干净；模拟 bootstrap 失败时 UI 不崩溃。

### Step 06: 提升运行时并发与配置鲁棒性

- 解决问题：`P08`、`P09`
- 范围：`tools/python_tools/adapter.go`、`app/app.go`
- 目标：临时脚本使用唯一文件名或专属临时目录；窗口状态保存能在配置缺失时自动恢复默认结构。
- 验收：并发运行同一 Python 工具不互相污染；删除 `app.json` 后仍能重新保存窗口状态。

### Step 07: 收口构建入口与默认环境策略

- 解决问题：`P10`、`P11`
- 范围：`scripts/build.go`、默认配置生成逻辑
- 目标：所有关键文件操作和校验失败都应显式中断；Windows 默认 Python 配置改为更稳妥的策略。
- 验收：脚本在失败时返回非零退出码；Windows 首启不再默认写死高风险解释器名。

### Step 08: 定义远程结果探测的最小约定

- 解决问题：`P15`
- 范围：`libs/core/toolspec/`、`libs/catalog/builtin/`、必要的 manifest
- 目标：先用启发式识别 `argKey: output` 和 `key` 为 `output` / `outputDir` 的路径参数；只对少量特例补显式覆盖。
- 验收：至少覆盖一个输出目录工具和一个输出文件工具，宿主能稳定判断结果位置。

### Step 09: 实现后端远程结果探测与手动下载

- 解决问题：`P13`
- 范围：`app/execution.go`、`app/internal/runtime/`
- 目标：远程任务结束后探测结果路径，对目录执行远端打包后下载，对单文件直接下载；下载动作仅由用户手动触发。
- 验收：成功任务和部分失败任务都可在结果存在时手动下载；结果不存在时提示明确原因。

### Step 10: 接通当前页签里的“下载结果”入口

- 解决问题：`P13`
- 范围：`ToolDetailPanel.vue`、`execution.ts`
- 目标：把“下载结果”放在当前工具页签这个主入口里，而不是先做重型历史系统。
- 验收：远程任务执行结束后，在当前页签可以顺手完成一次结果下载。

### Step 11: 实现参数级远程路径选择器

- 解决问题：`P14`
- 范围：`app/internal/runtime/`、`WorkspaceTabs.vue`、`ParameterPanel.vue`
- 目标：远程模式下点击路径参数的浏览按钮时，弹出远程路径选择器；本地模式继续走本地文件选择器。
- 验收：远程模式下至少能选择输入目录、输出目录和输出文件。

### Step 12: 为少量工具补最小语义覆盖

- 解决问题：`P14`、`P15`
- 范围：`libs/core/toolspec/`、少量 manifest
- 目标：只为启发式不准的工具补充远程工作路径 / 本地接收路径的最小覆盖，不重做整套 schema。
- 验收：至少一个历史特例工具在远程模式下行为正确。

### Step 13: 补轻量执行历史中的结果补位

- 解决问题：`P13`
- 范围：`execution.ts`、当前最近任务或快照消费点
- 目标：只保留短期回看所需信息，并提供补一次下载的入口。
- 验收：离开当前页签后，仍能从轻量历史补一次下载。

### Step 14: 实现独立 SSH 终端页签

- 解决问题：`P16`
- 范围：`app/internal/runtime/`、`WorkspaceTabs.vue`、SSH 列表入口
- 目标：基于已保存 SSH 连接打开独立终端页签，支持输入、回显、复制、断开和重连。
- 验收：能从连接管理直接打开一个可交互终端，不与工具页签状态深耦合。

### Step 15: 清理设置项、交互死角与残余文档

- 解决问题：`P12`、`P17`
- 范围：`SettingsModal.vue`、相关设置消费点、必要文档
- 目标：修正文案与真实快捷键行为；未接线设置要么接通，要么下线；文档只保留当前口径。
- 验收：所有显示给用户的设置说明都能被验证，入口文档之间不再打架。

## 3. 依赖关系

- `Step 02` 必须先于 `Step 03`，否则会在不安全前提下补功能。
- `Step 03` 必须先于 `Step 04`，否则 SSH UI 状态修正后仍缺真正可用的认证链路。
- `Step 08` 必须先于 `Step 09`，否则结果下载没有稳定依据。
- `Step 09` 必须先于 `Step 10` 和 `Step 11`，否则前端入口没有真实后端能力可接。
- `Step 12` 可以在 `Step 09` 后并行考虑，但不应早于安全收口步骤。
- `Step 14` 是独立能力，不应插到 `Step 09` 前面打断远程执行结果闭环。

## 4. 直接开工建议

如果现在就开始开发，推荐先做下面这个最小开发包：

1. `Step 11`：实现参数级远程路径选择器。
2. `Step 12`：为少量工具补最小语义覆盖。
3. `Step 13`：补轻量执行历史中的结果补位。
4. `Step 14`：实现独立 SSH 终端页签。
5. `Step 02`、`Step 03`：在合适时机回到 SSH 安全与认证收口。

这样做的原因：

- 远程结果闭环已经能用，下一步最影响体验的是“远程模式下浏览按钮仍走本地选择器”。
- 先补参数级远程路径体验，再补轻量历史和独立 SSH 终端，产品顺手程度提升最直接。
- SSH 安全与认证仍然重要，但当前不挡这条体验主线，可以放到下一轮安全收口单独推进。

## 5. 回归检查模板

每一步完成后至少执行以下检查：

```bash
go test ./...
go vet ./...
cd app/frontend && npm run lint
cd app/frontend && npm run typecheck
```

同时补做与该步骤直接对应的手工回归：

- 安全步骤：异常输入与恶意路径样例。
- SSH 步骤：密码认证、密钥认证、异常主机、失败提示。
- 结果下载步骤：结果存在、结果缺失、下载成功、下载失败。
- 路径选择步骤：本地模式、本地选择器、远程模式、远程选择器。
- 终端步骤：连接、回显、复制、断开与重连。
- 设置步骤：文案、快捷键、实际行为一一核对。
